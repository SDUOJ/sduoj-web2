# 开发中功能的可见性

未完成功能用路由字段 `devOnly: true` 标记。`availableRoutes` 同时过滤页面路由和导航树，并移除空菜单。父路由标记会覆盖整个子树，旧地址跳转同样需要标记。仅开发功能的客户端布局也保留此标记。

环境判断统一使用 `developmentFeaturesEnabled()`：

| 构建 | 开发中功能 |
| --- | --- |
| 本地 development | 显示，入口带 DEV 标签 |
| Jest / 隔离的 deployment=test 构建 | 显示，供回归测试 |
| production / release | 隐藏；直接访问对应路径返回 404 |

构建环境由 Webpack 注入，不从 URL、localStorage 或用户权限读取。隔离 test 构建仍遵循已有的本地测试域名限制。普通 release 构建无需额外参数即可关闭开发中功能。

当前标记范围：智能管理、模型与额度、任务管理、辅助批阅、考务管理、代码查重、课程管理、教室管理，以及对应的客户端工作台和兼容跳转。页面内的智能快捷入口、`FeatureAction` 抽屉、开发中的题目采集工具、用户组课程/课程管理页签也使用相同规则。用户组曾记住开发页签时，release 回到公告页签。

新增功能时：

1. 给路由加 `devOnly: true`，导航会自动显示 DEV 标签。
2. 现有页面内的入口用 `DevOnly` 包裹，文字旁放 `DevBadge`；判断页签时可直接使用统一环境函数。
3. 需要隐藏的内容及其子组件也放在条件内，避免挂载后请求未完成的接口。`FeatureAction` 已内置该规则。
4. 开发完成后移除对应标记和包裹，并确认 release 的直链和入口回归测试。
